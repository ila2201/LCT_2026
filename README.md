# Питомец Финни

Мобильная игра для детей 7–11 лет про карманные деньги. Ребёнок заводит питомца, каждую игровую неделю получает монетки, делит их на «Нужное», «Хочу» и «Копилку», покупает еду и игрушки, копит на цель и решает задания. От его решений зависят настроение питомца и то, как он растёт.

Монетки игровые: их нельзя купить или вывести. Регистрации, рекламы, покупок и сбора данных нет, интернет не нужен.

- Пакет: `ru.finnypet.app`
- Версия: `1.0.0`, номер сборки (versionCode): `1`
- Android 8.0+ (minSdk 26, targetSdk 36)
- Готовый APK: `dist/finny-pet-1.0.0.apk` (в git не хранится, прикладывается к релизу)

Подробная документация (архитектура, формулы, матрица требований, карта контента, тест-кейсы) лежит в [docs/Документация.docx](docs/Документация.docx), копия в PDF: [docs/Документация.pdf](docs/Документация.pdf).

## Как устроено

Один и тот же код работает как веб-страница и как Android-приложение:

- `www/`: само приложение, HTML, CSS и JavaScript без фреймворков и сборщиков;
- Capacitor 8 упаковывает папку `www/` в нативное Android-приложение (WebView);
- для веб-версии хватает любого статического сервера.

```
finny-pet/
├── www/                    приложение
│   ├── index.html
│   ├── css/style.css
│   ├── js/
│   │   ├── game.js         экономика игры: план, покупки, копилка, недели, рост (без DOM)
│   │   ├── task-check.js   проверка ответов в заданиях
│   │   ├── storage.js      сохранение в localStorage
│   │   ├── content.js      загрузка контента из JSON
│   │   ├── pet.js          рисунок питомца (SVG)
│   │   ├── ui.js           общие элементы интерфейса: шапка, листы, подсказки
│   │   ├── main.js         запуск, навигация, обработка нажатий
│   │   └── screens/        экраны игры
│   ├── content/            учебный контент и правила экономики (JSON)
│   ├── fonts/              шрифт Nunito (OFL)
│   └── sw.js               офлайн-кэш для веб-версии
├── android/                Android-проект Capacitor
├── tests/                  автотесты (node:test)
├── scripts/serve.js        локальный сервер для веб-версии
├── scripts/build-apk.ps1   сборка подписанного APK
└── docs/                   документация и скриншоты
```

Логика не знает про экран: `game.js` получает состояние и возвращает новое. Экраны только показывают состояние и вызывают функции логики. Задания, товары, цели, словарик и числа экономики лежат в `www/content/*.json`.

## Быстрый запуск

Нужен Node.js 20 или новее.

```bash
npm install
npm test        # автотесты
npm run web     # веб-версия на http://localhost:8080
```

Сервер выводит в консоль адрес в локальной сети, по нему можно открыть игру с телефона в той же Wi-Fi сети. Папку `www/` можно выложить на любой статический хостинг (GitHub Pages и т. п.). После первого открытия веб-версия работает без интернета.

Открывать `index.html` двойным кликом нельзя: браузер не загрузит модули и JSON по `file://`.

## Публикация на GitHub

1. Создать публичный репозиторий и отправить в него проект.
2. Веб-версия: Settings → Pages → Source: GitHub Actions. Workflow `.github/workflows/pages.yml` при каждом push в `main` прогоняет тесты и выкладывает папку `www/`. Адрес будет вида `https://<аккаунт>.github.io/<репозиторий>/`.
3. APK: Releases → Draft a new release → тег `v1.0.0`, приложить `dist/finny-pet-1.0.0.apk`.

Тесты запускаются на каждый push через `.github/workflows/tests.yml`.

## Сборка APK

Что нужно:

| Инструмент | Версия |
|---|---|
| Node.js | 20+ (проверено на 26) |
| JDK | 21 (Temurin) |
| Android SDK | platform `android-36`, build-tools `36.0.0` |
| Gradle | 8.14.3, скачивается сам через `gradlew` |

1. Установить JDK 21 и Android SDK, прописать `JAVA_HOME` и `ANDROID_HOME`. Если переменных нет, скрипт ищет `C:\android\jdk` и `C:\android\sdk`.
2. Создать ключ подписи (один раз):
   ```bash
   keytool -genkeypair -keystore signing/finny-release.jks -storetype PKCS12 -alias finny -keyalg RSA -keysize 2048 -validity 10000
   ```
3. Скопировать `android/keystore.properties.example` в `android/keystore.properties` и вписать пароль.
4. Собрать:
   ```bash
   npm run apk
   ```
   Готовый файл: `dist/finny-pet-1.0.0.apk`.

На macOS/Linux то же самое делается вручную:

```bash
npx cap sync android
cd android && ./gradlew assembleRelease
# android/app/build/outputs/apk/release/app-release.apk
```

Ключ `signing/` и `android/keystore.properties` в репозиторий не попадают (см. `.gitignore`). Если ключа нет, Gradle соберёт неподписанный APK.

Про кириллицу в пути: Gradle и утилиты Android на Windows плохо работают с не-латинскими путями. Скрипт `build-apk.ps1` в этом случае сам подключает папку проекта как временный диск (`subst`) и переносит кэш Gradle в `C:\android\gradle`.

Установка на телефон: скопировать APK и открыть (разрешить установку из этого источника) или `adb install dist/finny-pet-1.0.0.apk`.

## Демо-режим и сброс

**Демо-режим** нужен для экспертной проверки. Включается кнопкой «Демо-режим для проверки» на первом экране или в разделе «Взрослым». В нём:

- все 9 заданий и 6 разговоров в «Телефоне» открыты сразу (в обычном режиме они открываются постепенно, по неделям);
- на главном экране видна метка «ДЕМО».

Завершить неделю можно в любой момент после утверждения плана, в обоих режимах.

**Сброс профиля**: главный экран → «Взрослым» → решить пример → «Сбросить профиль и начать заново» (профиль удаляется, настройки остаются) или «Удалить все данные» (удаляется всё). Оба действия просят подтверждения.

### Сценарий проверки (Приложение А ТЗ)

1. Первый запуск → «Демо-режим для проверки» → три экрана знакомства.
2–3. Один экран: вид, пол, цвет, узор и имя питомца (реальные данные не нужны) → «Готово».
4. Приходит стартовый бюджет 100 монеток; на главном видны цель и задание.
5. «Составить план» → распределить ползунками с шагом 5 (например 45 / 25 / 30) → «Утвердить план».
6. «Задания» → любое задание, можно сначала ошибиться, потом «Ещё раз».
7. «Магазин» → купить еду и уход в «Нужном», игрушку в «Хочу». Вверху каждой вкладки виден «конверт»: сколько запланировано, потрачено и осталось. Покупка сверх плана вызывает предупреждение «Это больше плана»: можно отложить или всё равно купить, тогда в итогах не будет ⭐ за план. Покупка дороже кошелька не проходит, приложение объясняет, чего не хватает и что можно сделать.
8. «Копилка» → выбрать цель → «+10» / «+N по плану». «Взять из копилки» показывает, как изменятся сумма и срок.
9. На главном видно, что куплено и сколько потрачено от плана; питомец говорит, чего ему не хватает.
10. «Завершить неделю» → итоги: план и факт, звёзды роста, изменения питомца. Повторить неделю ещё 3–4 раза: после 5 ⭐ питомец становится «Подростком», после 10 ⭐ «Взрослым».
11. Закрыть и снова открыть приложение: всё на месте.
12. «Взрослым» → пример → прогресс, темы, бонус, сброс профиля.

Дополнительно: 📱 в шапке главного экрана открывает «Телефон». Там переписки с мамой, другом, бабушкой и мошенниками («вы выиграли приз», «мама с чужого номера», «подруга просит код из СМС»). Разговор длится 4–10 сообщений. За правильный разговор начисляются монетки, а если поверить мошеннику, монетки из кошелька пропадают (копилка и звёзды не трогаются), после каждого исхода короткий вывод. Это не чат между людьми: все собеседники заданы сценариями в `www/content/chats.json`.

## Тесты

```bash
npm test
```

73 теста на встроенном `node:test`, без зависимостей:

- `tests/game.test.js`: план, покупки, запрет минуса, копилка, срок до цели, награды, конец недели, звёзды и стадии, сквозной сценарий на 5 недель с проверкой, что монетки не появляются и не пропадают;
- `tests/tasks.test.js`: проверка ответов каждого типа; для каждого задания из контента есть правильное и ошибочное решение, все концовки сценариев достижимы;
- `tests/content.test.js`: минимальный объём контента по п. 2.6 ТЗ;
- `tests/chats.test.js`: у каждого разговора 4–10 сообщений на любом пути, есть верный и неверный исход; награда один раз, потеря не больше кошелька и без копилки.

Интерфейс дополнительно прогонялся по всему сценарию в headless Chrome на экране 360×760 (скриншоты в `docs/screenshots/`).

## Как добавить задание

Дописать объект в `www/content/tasks.json`, код менять не нужно. Поддерживаются типы:

| type | что делает ребёнок |
|---|---|
| `sort` | раскладывает вещи на «нужно» и «хочу» |
| `basket` | собирает корзину в пределах бюджета |
| `save` | выбирает, сколько откладывать в неделю, и видит расчёт по неделям |
| `scenario` | история с развилками и последствиями |
| `pay` | собирает монетами точную сумму |
| `number` | считает и вписывает число (чек, копилка) |

Пример:

```json
{
  "id": "gift",
  "topic": "savings",
  "type": "number",
  "week": 5,
  "reward": 15,
  "title": "Подарок другу",
  "skill": "Считать, сколько нужно отложить",
  "story": "Подарок стоит 60. В копилке 35. Сколько ещё нужно?",
  "lines": [{ "name": "Цена подарка", "price": 60 }, { "name": "Уже есть", "price": 35 }],
  "answer": 25,
  "right": "Верно, 25!",
  "wrong": "Из цены вычти то, что уже есть: 60 − 35."
}
```

`npm test` проверит, что у нового задания есть решение и все нужные поля. Для нового *типа* задания нужны функция проверки в `js/task-check.js` и отрисовка в `js/screens/task.js`.

## Данные и разрешения

- Хранится только на устройстве (localStorage WebView): питомец и его имя, монетки, план, покупки, копилка, цели, задания, настройки. Реальные имена, телефоны и почта не запрашиваются.
- Резервное копирование Android выключено (`allowBackup="false"`), данные не уходят в облако.
- Разрешение `INTERNET` нужно WebView Capacitor: игра открывается по внутреннему адресу `https://localhost`. Внешних запросов приложение не делает. Ещё AndroidX автоматически добавляет внутреннее разрешение `DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION` (уровня signature, пользователю не показывается). Других разрешений нет.
